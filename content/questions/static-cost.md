## 先给结论

静态博客省的不是「事」，而是「钱」和「风险」。事一点没少，只是从前置到了别处。

## 一笔账

| 项目 | 静态（本站） | 动态（WordPress 之类） |
| --- | --- | --- |
| 托管费用 | 零 | 服务器 + 数据库，年费若干 |
| 运维 | 无 | 系统补丁、备份、证书 |
| 被攻击面 | 几乎没有 | 插件、登录页、数据库 |
| 改版成本 | 改代码，全站生效 | 主题、插件互相打架 |
| 写作体验 | 写 Markdown、提交 | 后台编辑器，所见即所得 |
| 互动 | 需要外接（如评论服务） | 自带 |

## 换来的是什么

### 一、你把「发布」变成了「提交」

写完一篇文章，得打开终端：

```bash
git add .
git commit -m "post: 新的一篇"
git push
```

这三行对写过代码的人是肌肉记忆，对不写代码的人是一道墙。**这是静态博客真正的门槛，不是技术，是心理。**

### 二、没有后台，就没有搜索和归档

动态博客的归档、标签云、站内搜索都由数据库查询完成。静态站没有数据库，这些要么用构建时生成，要么像本站一样，在浏览器里读一份 `posts.json` 再筛。

文章多到几百篇时，这份 JSON 会变成新的负担。

### 三、评论得借别人的地方

静态页自己收不了评论。要么接第三方（多说早已关停，Giscus 依托 GitHub Discussions 算是当下的稳妥选择），要么干脆不收。

本站选择了不收——想说话，去 GitHub 开一个 Issue 就好。

## 那还值得吗

值得，如果满足两个条件：

1. 你愿意用 Git 与世界打交道；
2. 你希望十年后打开它，它还是它。

否则，去用现成的平台。**工具没有高下，只有合不合手。**
