## 先说结论

静态博客省的不是「事」，是「钱」和「风险」。事一点没少，只是从前置到了别处。

## 一笔账

| 项目 | 静态（本站） | 动态（WordPress 之类） |
| --- | --- | --- |
| 托管 | 免费（GitHub Pages） | 服务器 + 数据库 |
| 运维 | 无 | 补丁、备份、证书 |
| 被攻击面 | 几乎没有 | 插件、登录页、数据库 |
| 改版 | 改代码，全站生效 | 主题与插件互相打架 |
| 写作 | 写 Markdown、提交 | 后台编辑器 |

## 换来的麻烦

### 发布变成了提交

写完要跑三行：

```bash
git add .
git commit -m "post: 新的一篇"
git push
```

对写代码的人是肌肉记忆，对不写代码的人是一道墙。**这才是静态博客真正的门槛，不是技术，是心理。**

### 没有后台，就没有现成的归档

动态博客的归档、标签、搜索都由数据库查询完成。静态站没有数据库，只能像这个站一样，把信息塞进一个 JSON，再在浏览器里筛。

文章到几百篇时，这份 JSON 会变成新的负担。

### 评论得借别人的地方

静态页自己收不了评论。要么接第三方，要么干脆不收。这个站选择了不收——想说话，去 GitHub 开个 Issue。

## 那还值得吗

值得，如果你满足两个条件：

1. 愿意用 Git 与世界打交道；
2. 希望十年后打开它，它还是它。

否则，用现成的平台。**工具没有高下，只有合不合手。**
