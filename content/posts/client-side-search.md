## 没有后端

这个站没有数据库。所有文章的信息都在一个 `posts.json` 里：标题、日期、摘要、标签、分类。

搜索就是在浏览器里做字符串匹配。全站十几篇、几万字，一次遍历的耗时可以忽略不计。

## 分组，比排序更重要

搜索结果不是一堆混在一起的链接，而是按大类分开：

```
笔记   12
专栏    3
归档    8
标签   14
```

`归档` 和 `标签` 本身不是文章，而是聚合视图。所以结果里给的是「2026 年 10 月 · 3 篇」和「动效 · 4 篇」，点进去是归档页和标签页。这样它们能被搜到，又不会把同一篇文章重复列四遍。

## 实现只有三步

```js
function run(query) {
  const q = query.trim().toLowerCase();
  if (!q) return showEmpty();

  const hit = (item) =>
    (item.title + ' ' + item.text).toLowerCase().includes(q);

  const groups = [
    ['笔记', posts.filter(hit)],
    ['专栏', columns.filter(hit)],
    ['归档', archives.filter(hit)],
    ['标签', tags.filter(hit)]
  ];
  render(groups);
}
```

匹配范围只限标题与摘要。加正文当然也行，只是结果会变得嘈杂——命中一段代码的文章，未必是你想要的。

## 让人等的那一点

输入框做了 80 毫秒的防抖。不是为了性能，是为了不要在用户打到一半时反复重绘整页。

一次典型输入到出结果的时间在 16 毫秒以内，基本就是一帧。

> 搜索的体验不取决于快多少毫秒，而取决于「我打完最后一个字时，结果是不是已经在了」。
